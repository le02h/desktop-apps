# 功能规范：单次专注计时器

**功能目录**：`specs/001-single-focus-timer`

**创建日期**：2026-11-20

**状态**：草稿，待澄清

**需求来源**：在 Windows 桌面应用中完成一次可设置时长的专注计时，并通过键盘和 NVDA 获取状态及完成提示。

## Clarifications

### Session 2026-11-20

- Q: Windows 睡眠或休眠如何影响计时？ → A: 睡眠或休眠期间不从剩余时间逐步扣减。运行中的会话在恢复时若已超过原定结束时间，立即完成并提示。

## 用户场景与测试

### 用户故事 1：设置时长并完成一次专注（P1）

作为 Windows 桌面用户，我希望设置一次专注的时长并在结束时收到提示，以便专注期间无需一直查看计时器。

**优先理由**：设置、开始和完成构成最基本的专注流程。

**独立验证**：启动应用，将时长设为 1 分钟并开始，观察归零并确认提示。

1. 启动应用后，主窗口以简体中文显示，状态为待开始，剩余时间为 25 分钟。
2. 在待开始状态，将时长分别设置为 1 和 180 分钟，两种设置均被接受，剩余时间各自更新为完整时长。成功开始后进入运行中，倒计时从所设时长开始。
3. 一次 1 分钟会话自然归零时，剩余时间停在零，显示“专注完成”，在音频可用的环境中响一次提示音。保持窗口打开至少 10 秒，状态和剩余时间保持，提示音无重复，也无下一阶段自动开始。
4. 运行中进入 Windows 睡眠或休眠。若在原定结束时间前恢复，从挂起前的剩余时间继续。若恢复时达到或超过原定结束时间，应用恢复执行后立即停在零，显示“专注完成”，提示音只触发一次。

### 用户故事 2：暂停、继续、重置和退出（P1）

作为可能被打断的用户，我希望暂停后接着计时，也可以重置或关闭应用结束当前会话。

**优先理由**：用户需要能控制当前会话的进度和结束方式。

**独立验证**：设置 2 分钟并开始，依次验证暂停、继续和重置，再分别验证运行中和已暂停时关闭应用。

1. 运行中暂停后，状态变为已暂停。等待至少 3 秒，剩余时间保持。继续后，从暂停时的剩余时间递减。
2. 在运行中和已暂停时分别尝试通过键盘与鼠标改时长，当前设定及会话时长均保持。
3. 在运行中、已暂停及已完成时分别重置，均返回待开始、恢复当前设置的完整时长并允许修改。重置未完成的会话后，原会话到期时无完成提示或提示音。
4. 从运行中或已暂停状态关闭后重新启动，显示待开始和默认 25 分钟，原会话进度及设置均未恢复。

### 用户故事 3：通过键盘和 NVDA 操作并了解状态（P1）

作为使用键盘或 NVDA 的 Windows 用户，我希望独立完成计时操作，并按需读取剩余时间和状态。

**优先理由**：键盘与屏幕阅读器用户同样需要完成整个专注流程。

**独立验证**：在 Windows 上开启 NVDA，全程只用键盘，分别完成自然归零、重置及关闭流程。

1. 使用键盘能设置时长、开始、暂停、继续、重置并关闭窗口。操作顺序合理，焦点可见，状态切换使当前控件不可用时，仍可继续操作剩余可用控件。
2. 用 NVDA 导航至各交互控件时，可以获取其中文名称、角色和适用状态。按需读取时，可以获取当前剩余时间和待开始、运行中、已暂停或专注完成状态。
3. 开始、暂停、继续、重置和完成时，界面显示相应状态，NVDA 用户也能获知变化。连续运行至少 10 秒且不主动查询时，每秒刷新剩余时间不会触发自动播报。

### 边界情况

- 空值、非数字、小数、0、负数与大于 180 的输入不能成为已生效的时长。若界面允许这类内容暂时出现，提交时应给出可读取的中文反馈，并在输入有效前阻止开始。
- 运行中重复开始、已暂停时重复暂停、待开始时继续以及已完成时继续，都不会新建会话或改变当前状态。可以通过让操作不可用实现这一用户行为。
- 重置和自然结束只各自产生对应的状态结果。重置先发生时，旧会话不可随后完成。归零先发生时，该会话仍最多提示一次。
- 系统静音或音频不可用时，仍能看到并通过 NVDA 获取“专注完成”，剩余时间仍停在零。
- 用户手动暂停的会话在 Windows 恢复后仍为已暂停，剩余时间保持，直到用户继续或重置。

## 需求

### 功能需求

| 编号 | 可验证需求 | 对应用户故事 |
| --- | --- | --- |
| FR-001 | 启动后必须显示简体中文主窗口，状态为待开始，默认时长和剩余时间均为 25 分钟。 | 1、2 |
| FR-002 | 待开始时必须接受 1 至 180 分钟的整数时长，含两端。有效设置必须更新完整剩余时间，无效值按边界规则处理。 | 1 |
| FR-003 | 开始必须从当前完整时长进入运行中。同一时刻只允许一个专注会话，运行中和已暂停时必须锁定时长设置。 | 1、2 |
| FR-004 | 暂停必须冻结剩余时间，继续必须从保留的剩余时间恢复倒计时。所有操作遵循状态转换表。 | 2 |
| FR-005 | 重置必须回到待开始，恢复当前设置的完整时长，解锁设置并结束旧会话。 | 2 |
| FR-006 | 自然归零或从睡眠或休眠恢复时判定超期，均必须停止计时并显示“专注完成”，剩余时间保持为零，每次完成只触发一次提示音。 | 1 |
| FR-007 | 关闭应用必须结束当前会话。重新启动必须使用默认状态和时长。 | 2 |
| FR-008 | 必须支持纯键盘完成全部操作。交互控件必须具有合理的焦点顺序和可见焦点。 | 3 |
| FR-009 | NVDA 必须能够读取控件名称、角色、适用状态、剩余时间与当前计时状态。状态变化必须可察觉，每秒时间刷新不得触发自动播报。 | 3 |
| FR-010 | 睡眠或休眠期间必须保留挂起前的剩余时间。运行中会话以挂起前的剩余时间推算原定结束时间，恢复时达到或超过该时间必须立即完成，否则按保留的剩余时间继续计时。 | 1、2 |

### 状态转换

| 当前状态 | 触发条件 | 下一状态 | 可观察结果 |
| --- | --- | --- | --- |
| 应用未打开 | 启动应用 | 待开始 | 显示主窗口和完整 25 分钟，可改时长。 |
| 待开始 | 提交有效时长 | 待开始 | 剩余时间更新为所设的完整时长。 |
| 待开始 | 开始且时长有效 | 运行中 | 从完整时长递减，锁定时长。 |
| 运行中 | 在归零前暂停 | 已暂停 | 保留剩余时间，保持时长锁定。 |
| 已暂停 | 继续 | 运行中 | 从保留的剩余时间递减，保持时长锁定。 |
| 运行中 | 自然归零 | 已完成 | 停在零，显示“专注完成”，触发一次提示音。 |
| 运行中 | 从睡眠或休眠恢复，早于原定结束时间 | 运行中 | 从挂起前的剩余时间继续计时，无完成提示。 |
| 运行中 | 从睡眠或休眠恢复，达到或超过原定结束时间 | 已完成 | 恢复执行后立即停在零，显示“专注完成”，触发一次提示音。 |
| 已暂停 | 从睡眠或休眠恢复 | 已暂停 | 保留暂停时的剩余时间，无完成提示。 |
| 任一窗口状态 | 重置 | 待开始 | 恢复当前设置的完整时长，可改时长。 |
| 任一窗口状态 | 关闭应用 | 应用未打开 | 关闭窗口，结束会话。 |

表中未定义的状态操作不会改变会话状态。待开始时重置等同于恢复当前有效设置的完整时长。

### 关键实体

- **专注设置**：由用户在本次应用运行期间选定的整数分钟数，初始为 25。
- **专注会话**：一次从开始到完成、重置或关闭的计时过程，包含本次设置的时长、剩余时间及当前状态。

## 成功标准

### 可衡量结果

- **SC-001**：在系统持续唤醒、会话未暂停的验收场景中，1 分钟会话在 60 秒后完成，以界面显示精度计允许 1 秒误差。完成后显示零和“专注完成”，音频可用时听到一次提示音。
- **SC-002**：时长边界验证中，1 和 180 均可应用，空值、非数字、小数、0、负数和 181 均无法作为时长开始计时。运行中及已暂停时的全部改时长尝试均不改变设置。
- **SC-003**：暂停至少 3 秒后，剩余时间与暂停时一致，继续后开始递减。分别从运行中、已暂停和已完成重置，三种场景均恢复当前完整时长和设置权限。
- **SC-004**：在 Windows 上，纯键盘可完成设置、开始、暂停、继续、重置和关闭这六类操作。NVDA 可读出全部交互控件的名称、适用状态及当前剩余时间，用户可获知四种计时状态，连续 10 秒倒计时不产生由每秒刷新引发的自动播报。
- **SC-005**：从运行中和已暂停状态分别关闭并重新启动，两次均回到待开始和默认 25 分钟。
- **SC-006**：睡眠与休眠分别验证三种恢复场景。运行中提前恢复时按挂起前的剩余时间继续，运行中达到或超过原结束时间才恢复时立即完成且只提示一次，已暂停时恢复后仍保持原剩余时间。

## 假设

- 已完成时，先重置再修改时长或开始新会话。这是当前规范采用的交互默认值。
- 提示音可听性以 Windows 音频输出可用且未静音为前提。
- 范围限于用户手动控制的单次专注会话。自动休息、循环、历史统计、持久化、系统托盘和安装包均在本次范围之外。
- 恰好在原定结束时间恢复时按超期分支处理。

- **待澄清**：应用窗口处于后台时，完成状态是否需要由 NVDA 自动播报。

- **需要技术验证（Windows 睡眠与休眠）**：在支持相应电源状态的 Windows 设备上实测能否识别挂起和恢复、保留正确的剩余时间，并在恢复执行后按时完成且避免重复提示。
- **需要技术验证（Qt 与 NVDA）**：实测窗口前台及后台的完成提示、状态变化的可发现性、失焦控件后的键盘操作，以及每秒刷新是否会触发朗读。
- **需要技术验证（Windows 音频）**：实测自然完成和恢复后完成各只播放一次提示音，并确认静音或音频不可用时仍能读取完成状态。
